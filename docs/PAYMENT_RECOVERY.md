# 현금 오류 자동 복귀와 결제 잠금 복구

## 1.3.7 현금 오류 자동 복귀

잔돈·현금 반환 실패가 기록된 현금 거래는 관리자 코드 없이 원본을 암호화 보관하고 첫 화면으로 돌아간다.
숙박대금을 전부 받았더라도 예약 생성·입실·객실 비밀번호 안내를 진행하지 않는다.
이전 고객의 선택 객실과 입력값을 비우며 자동 반환·추가 지급 명령은 보내지 않는다.

PMS의 **키오스크 판매 → 키오스크 현금·잔돈 확인**에 발생 시각, 숙소·동·선택 객실,
오류 사유, 총 투입액, 반환 확인액, 기록상 잔액, 당시 잔돈을 `입실 중단 / 정산 확인 필요`로 남긴다.
이 금액은 현금 장비의 기록이며 실제 지급 여부나 고객 정산 완료를 뜻하지 않는다.
입실을 중단하므로 잔돈만이 아니라 수납된 전체 금액의 정산 여부를 확인해야 한다.

인터넷/PMS 장애 때는 PC의 암호화 보관 파일을 유지하고 30초 간격 및 앱 재시작 시 재전송한다.
네이티브 서명과 해당 숙소·동을 검증한 기록만 `kiosk_payment_incidents/<동일 ID>`에 저장한다.
중복 요청은 기존 기록을 덮어쓰지 않으며 전화번호·객실 비밀번호·원본 예약은 PMS 오류 목록에 보내지 않는다.

마지막 장비 요청 후 약 4초부터 자동 보관을 시도한다. 지폐 투입구의 정지 확인과 암호화 저장이
실패하면 기존 거래를 유지하며 5초 후 다시 시도한다. 이 경우 자동 복귀가 지연될 수 있다.
단순 앱 중단으로 결과를 모르는 기록, 카드 승인 증빙, 이미 저장 요청을 보낸 예약, 손상되거나
저장에 실패한 거래는 아래 관리자 복구 절차를 유지한다.

## 관리자 복구 대상

설치형 키오스크의 `결제 처리 확인이 필요합니다` 화면에서 사용한다.
1.3.6 이상 설치본으로 업데이트해야 버튼이 표시된다. 기존 1.3.5에는 없다.

## 현장 절차

1. 진행 중인 고객 거래가 없고 장비 요청이 끝났는지 확인한다.
2. 잠금 화면의 **관리자 복구**를 누르고 기존 관리자 비밀번호로 인증한다.
3. 화면의 결제 방식, 남은 현금, 반환액, 예약 처리 확인번호를 실제 거래와 비교한다.
4. 실제 처리 결과를 선택하고 확인란을 체크한다.
   - **현금 미투입 취소**: 기록상 현금 0원이고 승인/예약 처리 증거가 없는 현금 건에서만 표시된다. 실제 미투입도 확인한다.
   - **승인 내역 없음 확인**: 현금이 기록되지 않은 카드 건에서만 표시된다. 토스 단말기/승인 내역에서 직접 확인해야 한다. 연결 오류나 `복구할 승인 결과 없음` 문구만으로 미승인을 확정하지 않는다.
   - **관리자 정산 완료**: 실제 카드 승인/취소, 현금 투입/반환 및 예약 처리 결과를 확인하고 필요한 조치를 별도로 마친 경우 사용한다.
5. **기록 보관 후 처음으로**를 누른다. 성공하면 이전 객실 선택과 입력값을 비우고 첫 화면으로 돌아간다.

이 작업은 카드 승인·취소, 현금 반환, 예약 생성·취소를 실행하지 않는다.
따라서 실제 환불/입실 처리가 필요한 거래를 화면 잠금 해제만으로 완료 처리하면 안 된다.

## 실패할 때

- 진행 중 요청: 요청이 끝난 뒤 다시 시도한다. 인식기 명령 직후에는 3.5초 이상 기다린다.
- 투입구 정지 응답 없음: 현금 관련 건은 인식기 연결 상태를 확인하고 다시 시도한다. 정지 실패를 무시하거나 전체 데이터를 지우지 않는다.
- 기록 변경: 바뀐 거래 내용과 실제 처리 결과를 다시 확인한다.
- 보관/암호화/잠금 해제 실패: 기존 거래를 유지한다. 디스크와 해당 Windows 계정을 확인한다. 비밀번호 오류 5회 시 1분 후 재시도한다.

카드만 사용했고 현금 관련 기록이 없는 건은 미연결 현금 장비 때문에 복구를 막지 않는다.
카드 연결 장애 자체를 고치거나 토스 플러그인을 업데이트하는 기능은 아니다.

## 보관 및 보안

- 기존 관리자 인증을 재사용하되 최종 보관 요청도 Electron 메인 프로세스에서 다시 인증한다.
- 같은 키오스크의 `http://localhost:3000` 메인 화면만 허용한다. 중복 복구와 동시 결제 요청을 차단한다.
- `%APPDATA%` 아래 해당 앱의 `userData/payment-recovery-archive/<해시>.bin`에 Electron safeStorage로 암호화한다. 계정/환경에 따라 실제 userData 경로는 다를 수 있다.
- 저장된 원본 문자열과 저장 실패 등으로 화면에만 남은 거래 정보도 함께 보관한다. 손상된 원본은 재해석해 덮어쓰지 않는다.
- 기록에 확인 시각, 앱 버전, property/동, 처리 사유를 남긴다. 비밀번호는 저장하지 않는다.
- 파일 동기화와 복호화 검증을 마친 뒤 화면이 같은 거래인지 재확인하고 `kiosk-payment-recovery-v1` 하나만 해제한다. 원본/화면이 바뀌면 해제하지 않는다.
- 응답 유실 시 동일 거래·처리 사유의 보관 파일을 재사용한다. 기존 보관 파일을 덮어쓰지 않는다.
- 등록 정보, `.env.local`, 장비 설정 및 다른 localStorage 항목은 변경하지 않는다. 원본 보관 파일은 같은 Windows 계정에서 관리자 도구로 복호화해야 하며 운영자 승인 없이 외부로 보내지 않는다. 현금 자동 복귀의 최소 오류 기록만 위 PMS 경로로 전송한다.

## 검증 범위

`npm.cmd run build`에 관리자 인증, 금액/처리 사유 검증, 암호화 보관, 동시 실행,
정지 응답/실패/시간 초과, 원본 변경 및 저장 실패 회귀 검사를 포함한다.
브라우저 가상 거래로 인증 오류, 현금 0원·카드·손상 기록 복구, 보관 실패 및 첫 화면 복귀를 별도 확인한다.
실제 Windows safeStorage 암호화는 격리한 가상 기록으로 검증한다.
실물 인식기 정지 응답과 현장 토스 연결은 별도의 현장 검증 대상이다.
