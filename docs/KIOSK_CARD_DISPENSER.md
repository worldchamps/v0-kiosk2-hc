# SNR-K750L 카드키 현장 시험

이번 단계는 관리자 화면에서 원본 카드 등록, 공카드 1장 시험 발급, 반납을 확인하는 기능이다. 고객 체크인의 자동 발급과 PMS 처리, 원격 장애 전송은 아직 연결하지 않았다. 카드 기록 성공만으로 도어락 호환 성공으로 판단하지 않는다.

## 적용 대상과 설정

- 최초 현장 적용 대상: C·D동 `property1-kiosk-01`.
- 코드에서 허용하는 PC: `property1`, 또는 `property3`이면서 `KIOSK_BUILDING=A`. 이외 숙소와 B동은 카드 포트를 열지 않는다.
- 기본값은 꺼짐. 관리자 장비 설정에서 실제 카드 발급기 COM 포트와 **장비 주소 (Device Number)**를 입력하고 **관리자 카드키 시험 기능 사용**을 켠 뒤 재시작한다. 다른 장비와 같은 COM 포트는 저장할 수 없다.
- 장비 주소는 제조사 데모의 Device Number와 같게 지정한다(00~15). 2026-10-07 C·D동 현장 데모 화면에서는 `COM3`, `9600bps`, `Device Number: 08`을 확인했다. 이 장비는 주소 `08`을 입력한다. 다른 PC의 주소로 고정하지 않는다.
- 로컬 설정: `CARD_DISPENSER_ENABLED=true`, `CARD_DISPENSER_PORT=실제 COM 포트`, `CARD_DISPENSER_ADDRESS=실제 장비 주소`(미설정 시 `00`). RS232는 9600/8/N/1이다.
- 제조사 데모 프로그램은 종료한다. 테스트 중 고객 거래가 없어야 하며 직원이 장비 앞에 있어야 한다.

## 현장 확인 순서

1. 관리자 모드의 **카드키** 탭에서 관리자 인증 후 **장치 상태**를 확인한다.
2. 객실 호수(C/D동이면 `C101` 또는 `D101` 형식)를 입력하고 원본 카드 등록을 누른 뒤, 안내에 따라 원본을 앞 투입구에 넣는다. 읽기가 끝나면 앞쪽에 나온 원본을 가져간다. 같은 호수의 기존 등록을 교체하려면 등록일시를 확인하고 교체 체크를 한다.
3. 카드함에 준비한 Mifare 1K CUID 공카드를 넣고 **공카드 1장 시험 발급**을 실행한다. 나온 카드를 가져간 뒤 실제 해당 객실 도어락에서 개폐를 확인한다. 직원이 원본 카드로도 같은 문을 확인하여 두 결과를 구분해 기록한다.
4. **시험 카드 반납**을 누르고 발급된 카드를 앞 투입구에 넣는다. 카드함으로 이동하는지 확인한다. 체크아웃이나 예약 정보는 변경하지 않는다.
5. 같은 흐름을 3회 반복하고, 등록·기록·검증·수령·문 개폐·반납 결과를 각각 기록한다. 센서의 실제 위치와 카드 이동은 현장에서 확인해야 한다.

## 카드 데이터 범위

원본 카드는 읽기만 한다. 이번 시험은 공장 기본 인증키 `FFFFFFFFFFFF`와 재기록 가능한 기본 접근권한 `FF0780`을 사용하는 카드만 지원한다. 읽을 수 없는 인증키를 추측하거나 여러 키로 탐색하지 않는다. 인증 실패 시 실패 섹터를 표시하고 등록을 중단한다.

발급 시 일반 데이터와 확인된 기본 섹터 트레일러를 기록하고 다시 읽어 검증한다. 숨겨진 Key A가 0으로 읽혔다고 0을 복사하지 않으며, 인증에 성공한 설정값을 사용한다. **블록 0은 쓰지 않고 카드 고유번호(UID)도 변경하지 않는다.** UID로 출입을 판단하는 도어락에서는 이 시험 카드가 열리지 않을 수 있다. 현재 결과로 다른 모델의 호환성을 보장하지 않는다.

객실별 원본 데이터·UID·인증키는 해당 Windows PC의 Electron `safeStorage`로 암호화해 사용자 데이터 폴더의 `card-keys`에 원자적으로 저장한다. 화면에는 호수·등록일시·성공/실패 정보만 전달하며 원본 바이트, UID, 인증키를 브라우저·콘솔·클라우드로 보내지 않는다. 파일을 다른 PC로 복사하여 사용하는 기능은 없다.

## 실패와 회수

- 카드 이동·기록·검증·배출은 전체 30초 예산으로 실행한다. 기록/검증 실패 때만 실패 카드를 회수함(CP)으로 보낸 뒤 새 카드로 1회 재시도한다. 이 재시도도 같은 시간 예산을 사용한다.
- 앞쪽에 배출한 카드를 60초 동안 가져가지 않으면 회수함으로 회수한다. 원본 카드도 미수령 시 회수함에서 직원이 찾아야 한다.
- 카드 위치를 확정하지 못하면 추가 발급·화면 전환·업데이트 설치를 막는다. 장치 상태와 실제 카드를 확인하고 필요하면 **회수함으로 회수**를 실행한다. 빈 장비에서만 초기화를 실행할 수 있다.
- 장비 연결 실패·카드 부족·걸림·회수함 가득 참은 자동으로 성공 처리하지 않는다. COM 포트나 장비 주소를 저장한 뒤에는 앱을 다시 시작한다. 단순 연결 문제를 해소한 뒤 **장치 상태**를 다시 누르면 해당 포트를 다시 열고 필요 시 이전 통신을 취소·비운 후 상태만 조회한다. 이 동작은 카드를 이동하거나 기록하지 않는다.
- 통신 실패에는 포트·속도·주소·실패 단계·수신 바이트 수를 표시한다. 상태 조회만 실패한 경우에는 화면 전환·업데이트를 잠그지 않는다. 카드 이동 중 생긴 미확정 상태는 실패한 조회로 해제하지 않으며, 성공한 상태 조회에서 장비가 비어 있고 이동 중이 아님을 확인해야 해제한다.
- 원본 읽기에 실패해도 원본 카드를 앞쪽으로 돌려주고 수령을 기다린다. 카드가 반환되었다는 사실은 등록 성공을 뜻하지 않는다. 최종 오류에는 실패 명령·블록 번호·제조사 오류코드 또는 응답 길이를 표시하며, 반환 명령의 성공으로 최초 읽기 오류를 덮어쓰지 않는다. 원본 내용과 UID·인증키는 진단 정보에 포함하지 않는다.
- 시험을 중단하려면 카드가 남아 있지 않은지 확인한 뒤 장비 설정에서 카드키 기능을 끄고 재시작한다.

## 검증 범위

자동 검사는 가상 RS232 응답, 프레임 분할·BCC·ACK/NAK·시간 제한, 인증 실패, 쓰기 후 재검증, 1회 재시도, 미수령 회수, 블록 0 쓰기 금지, 장비별 차단, 관리자 인증, 암호화 저장과 중복 발급 차단을 확인한다. 실제 카드 이동·도어락 개폐는 자동 검사와 별도의 현장 확인 대상이다.
